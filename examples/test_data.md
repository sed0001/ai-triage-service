# Тестовые данные для POST /triage

Готовые текстовые обращения для проверки сервиса. Отправляйте их как `text`
в JSON-запрос к `POST /triage` (см. README, раздел «Контракт API»).

```json
{
  "text": "<текст обращения из таблицы>",
  "channel": "<channel из таблицы>",
  "client_id": "<client_id из таблицы>"
}
```

## Обращения

| № | channel    | client_id    | text                                                                                          | Ожидаемая category | escalate |
|---|------------|--------------|-----------------------------------------------------------------------------------------------|--------------------|----------|
| 1 | `email`    | `test-001`   | Здравствуйте! Мне дважды списали деньги за подписку, верните, пожалуйста, один платёж.          | `billing`          | —        |
| 2 | `chat`     | `test-002`   | Подскажите, как поменять тариф на более дешёвый?                                               | `billing`          | —        |
| 3 | `form`     | `test-003`   | После оплаты не открывается личный кабинет, что делать?                                         | `support`          | —        |
| 4 | `email`    | `test-004`   | Это безобразие! Сервис вообще не работает, я ничего не могу скачать. Верните деньги!            | `complaint`        | `true`   |
| 5 | `chat`     | `test-005`   | Подскажите, во сколько закрывается пункт выдачи?                                                 | `other`            | —        |
| 6 | `email`    | `test-006`   | Хочу оформить возврат товара из заказа № 12345, как это сделать?                                | `billing`          | —        |

## Пример готового запроса

```bash
curl -X POST http://127.0.0.1:8000/triage \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Здравствуйте! Мне дважды списали деньги за подписку, верните, пожалуйста, один платёж.",
    "channel": "email",
    "client_id": "test-001"
  }'
```

## Комментарии

- Ожидаемые категории — ориентир для демо. Модель может классифицировать
  пограничные случаи иначе (например, №2 иногда относится к `support`),
  это допустимо: система честно отвечает по тексту и ставит `confidence`.
- Обращение №4 демонстрирует эскалацию: эмоциональный/конфликтный тон
  должен приводить к `escalate: true`.
- Сценарий «если всё сломалось» проверяется ошибкой LLM при заданном `LLM_API_KEY`
  (или текстом без совпадения в демо-режиме): возвращается `escalate: true`
  и шаблонный ответ «передано оператору».
- Без `LLM_API_KEY` сервис работает в демо-режиме базы знаний: приведённые выше
  тексты вернут свои ответы из `examples/knowledge_base.json` один в один,
  поэтому демо можно прогнать вообще без ключа и без сети.
